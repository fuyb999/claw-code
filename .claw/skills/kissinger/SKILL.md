# 何时使用

当议题涉及秩序重构、战略稳定、外交交易、历史类比、领导人博弈或均势设计时使用。

如果用户只关心短线市场情绪或单一数据点，不要单独依赖这个视角。

# 输入约束

- 只把“基辛格”视为分析框架，不要伪造真实发言或现实参与。
- 优先围绕历史先例、外交安排、战略稳定、利益交换等维度组织资料检索。
- 只使用当前线程可见的数据来源。

# 工作步骤

1. 先调用 `MemorySearch`，检查是否已有同类议题的历史类比、秩序判断或谈判边界。
2. 优先调用 `EsSearch`，围绕“历史类比、均势、外交安排、战略稳定、领导人、谈判”等维度构造检索 query。
3. 需要补正文时，使用 `SourceSearch` / `SourceRead`、`WebFetch` 或 `DbQuery` 读取相关资料。
4. 基于证据提炼：
   - 可类比的历史时刻
   - 当前各方核心利益
   - 是否存在稳定均势或交易空间
   - 哪些事件意味着秩序接近重构
5. 调用 `TopicDriftCheck`，确保回答仍然回到当前决策问题，而不是变成外交史综述。
6. 用 `ArtifactEmit` 输出 `markdown` 专家卡，标题建议为 `专家视角 / 基辛格`。
7. 对可复用的卖出/减仓/转向信号等稳定规则，调用 `MemoryWrite` 记录。

# 输出要求

- 默认按以下结构输出：
  - 历史类比
  - 当前秩序状态
  - 核心利益与交易空间
  - 稳定 / 失稳信号
  - 对用户决策的含义

# 记忆策略

- 只沉淀稳定的判断框架和事件触发器。
- 不把长篇历史论述原样写入长期记忆。

# 偏题控制

- 一旦开始铺陈人物经历或外交史细节，立即回到“哪些结构信号会改变当前判断”。

# 禁止事项

- 不要伪造原话、闭门谈判细节或现实背书。
- 不要展示内部工具输出、路径或后台配置。
