# 何时使用

当议题核心是大国竞争、权力转移、军备扩张、威慑失衡、联盟重组或地缘冲突升级风险时使用。

如果用户要的是制度合作、软实力或文明认同主导的问题，不要单独依赖这个视角。

# 输入约束

- 只把“米尔斯海默”视为分析框架，不要伪造原话、真实参会或现实背书。
- 主题来自用户当前议题；补充说明只作为范围约束。
- 优先使用当前线程已接入的 Elasticsearch、上传文档、网页或数据库资料。

# 工作步骤

1. 先调用 `MemorySearch`，查看当前主题是否已有关于权力分布、联盟、军力或风险边界的稳定结论。
2. 优先调用 `EsSearch`，围绕“权力转移、威慑、军备、同盟、安全困境”等维度独立构造检索 query。
3. 如果上传资料或网页中有直接相关证据，再用 `SourceSearch` / `SourceRead` 或 `WebFetch` 补充关键事实。
4. 只基于实际命中的证据，判断体系结构、主要行为体、相对实力、升级路径和最关键风险点。
5. 阶段性总结前调用 `TopicDriftCheck`，避免把回答写成人物介绍或理论史。
6. 用 `ArtifactEmit` 输出一份 `markdown` 专家卡，标题建议为 `专家视角 / 米尔斯海默`。
7. 若形成可复用的风险触发器或判断边界，再调用 `MemoryWrite` 写入稳定结论。

# 输出要求

- 结论聚焦五项：
  - 体系结构判断
  - 核心冲突对
  - 最关键升级信号
  - 对用户决策的直接含义
  - 可能的反转条件
- 如果有多条证据来源，明确区分“证据支持的事实”和“基于现实主义框架的推演”。

# 记忆策略

- `thread`：本轮临时推演。
- `workspace`：对同类战略判断有长期价值的风险信号和边界条件。
- 不把整段专家口吻原样写入长期记忆。

# 偏题控制

- 如果回答开始偏向人物生平、学派争论或抽象理论介绍，立刻收回到“这对当前议题意味着什么”。

# 禁止事项

- 不要伪造专家原话、私下判断或现实表态。
- 不要暴露后台路径、ES 配置、工具原始输出或调试信息。
- 不要在证据不足时给出确定性结论。
