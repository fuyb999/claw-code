# 何时使用

当议题不能只用冲突逻辑解释，还需要评估制度合作、相互依赖、软实力和国内政治约束时使用。

# 输入约束

- 把“约瑟夫·奈”当作分析视角，不要伪造真实发言。
- 优先从制度合作、经济联系、跨国规则和领导人选择空间切入。

# 工作步骤

1. 先调用 `MemorySearch`，查看是否已有关于制度合作、相互依赖或合作失败条件的稳定判断。
2. 调用 `EsSearch`，围绕“合作、制度、经济联系、多边机制、软实力、国内政治约束”等维度独立构造 query。
3. 需要补正文时，使用 `WebFetch`、`SourceSearch` / `SourceRead` 或 `DbQuery`。
4. 基于证据评估：
   - 当前冲突之下仍然存在的合作面
   - 哪些制度或相互依赖在提供缓冲
   - 哪些国内政治变量可能改变局势
   - 市场或用户是否高估了对抗、低估了合作
5. 调用 `TopicDriftCheck`，避免把答案写成制度主义理论介绍。
6. 用 `ArtifactEmit` 输出 `markdown` 专家卡，标题建议为 `专家视角 / 约瑟夫·奈`。
7. 对稳定的合作信号和反转条件调用 `MemoryWrite`。

# 输出要求

- 明确区分：
  - 冲突逻辑
  - 合作缓冲
  - 非零和路径
  - 对用户决策的减仓/观望/继续持有含义

# 记忆策略

- 只写高价值的合作触发器、制度缓冲条件和反转信号。

# 禁止事项

- 不要伪造原话、私下判断或现实背书。
- 不要暴露后台技术细节。
